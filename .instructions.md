# Programming and Quantitative Methods in Finance — Lesson Structure

## Overview

12-lesson (12 x 90 minute) introductory Python course, taught in **English**, for
absolute-beginner finance masters students. The course follows the **python_psz**
online materials (the "Programozás alapjai" mirror) topic by topic, adapted for a
quantitative-finance audience.

Source template (local mirror):
`../ProgramozasAlapjai/course_mirror/python_psz/index.html`

The individual topic pages live in the sibling folders
`../ProgramozasAlapjai/course_mirror/python_basic/` and
`../ProgramozasAlapjai/course_mirror/python_advanced/`. Sample data files live under
`../ProgramozasAlapjai/course_mirror/python_psz/pandas/` and `.../mintazh2/`.

## Reusable class-design workflow

Use this workflow when starting a similar course in another repository. Adapt the
course name, audience, duration, source mirror, subject matter, and assessment
rules; keep the ordering and deliverables.

1. Inspect the current course-level source and the repository instructions before
   editing. Preserve user edits and treat the current course-level deck as the
   authoritative outline.
2. Locate the source course's top-level index page. Read the linked pages for the
   selected class, following links recursively rather than relying on the index
   text alone. For HTML source, inspect the visible headings, examples, code,
   exercises, and linked setup pages.
3. Translate source material into English and adapt examples to the target
   audience. Do not copy the source wording verbatim. Use concrete, fully
   specified domain scenarios rather than generic programming prompts.
4. Keep `CourseTopics.tex` course-level: structure, schedule, assessment, and
   high-level links only. Move class-specific setup, notebook, concept, and
   exercise material into the class deck.
5. Create each class in a folder named `NN_ContentOfClass`, for example
   `01_BasicsVariablesStrings`. The class deck is
   `ContentOfClass.tex` and includes, in teaching order, setup prerequisites,
   the first runnable task, linked tool/workflow material, core concepts, and
   in-class exercises.
6. Put the first runnable exercise immediately after the required environment is
   installed. For Python classes this is normally a Hello World task immediately
   after Python and VS Code setup.
7. Keep exercise materials concrete and usable in class: include task wording,
   expected constraints, and runnable examples. The class companion file should
   contain the runnable examples that match the deck.
8. Build every LaTeX document with intermediates in a local `build/` directory:
   `latexmk -pdf -synctex=1 -interaction=nonstopmode -file-line-error
-outdir=build <Document>.tex`. Fix compilation errors and overfull boxes before
   finishing.
9. Do not create quizzes unless the user explicitly requests them. When quizzes
   are requested, create the specified notebook files separately from the class
   deck and validate each answer cell independently.

For a new course, begin by changing the course-specific sections below rather than
assuming the Python topics, source paths, finance examples, or 12-class schedule
apply unchanged.

## Adjustments to the python_psz materials

- **English.** The source pages are in Hungarian. All materials produced here are
  written in English — adapt and translate the python_psz content, do not copy it.
- **Finance-themed.** All examples, worked examples, tests, and quiz questions use
  fully specified finance scenarios (bonds, portfolios, dividend yields, returns,
  loans, interest), matching a quantitative-finance masters audience.
- **Read the whole page tree, not just `index.html`.** Several topic folders have
  sub-pages: `installation/` has `python.html`, `vscode.html`, `environment.html`;
  `function/` has `function_args.html`. `sequence_types/index.html` is a _hub page_
  whose real content is in the pages it links (`list/`, `range/`, `tuple/`,
  `variables_text/`). Some `index.html` files are bare Apache directory listings
  (`python_basic/introduction/`, `python_psz/mintazh1/`, `mintazh2/`) — the content
  there is the linked PDF/ipynb, not the page.
- **Present in the mirror but NOT in the python_psz menu, and deliberately excluded:**
  `python_advanced/numpy/` (decided: left out — the 12 lessons are full, and pandas is
  taught without an explicit NumPy layer), and the extra sorting variants
  `heap_sort.html` / `merge_sort.html`. Note the mirror has _four_ sorting pages
  (bubble, insertion, heap, merge); the menu links only the first two. All are skipped.
- **Sorting algorithms are skipped** (Rendező algoritmusok / Buborék rendezés /
  Beszúró rendezés) **and search algorithms** (Kereső algoritmusok — linear and
  binary search) are skipped; neither is covered.

## Course-Specific Lesson Plan (12 x 90 min)

The table below is planning data for this repository, not a reusable template.
When adapting this workflow to another course, replace the table completely with
that course's duration, class numbering, folder names, source pages, and
assessment placement before generating class materials.

New material is taught in **Lessons 1–10**. **Lesson 11 is practice + mock exam**
(no new material) and **Lesson 12 is the in-class exam**. Lesson 1 is deliberately
light because roughly half of it is spent on hands-on Python installation. The data
half of the course gets three lessons (8–10: Pandas I, Pandas II, visualization).

The former standalone `datetime` / `math` / `help` lesson was dissolved and spread
into its neighbours — `math` and `help` join the modules topic in Lesson 7, and
`datetime` becomes the short prerequisite segment opening Lesson 8 (it feeds pandas
date handling). That is what frees Lesson 11 for practice and the mock exam.

## Lesson Folder Structure

- Folder name: `NN_ContentOfClass` (e.g. `01_BasicsVariablesStrings`)
- Initial class materials: `ContentOfClass.tex` and
  `ContentOfClass_class.py` (or `.txt`). Add test files or notebooks only when
  explicitly requested.
- `00_CourseLevelDocuments` is not a lesson: it holds course-wide documents, chiefly
  `CourseTopics.tex` (the two-level topic list mirroring this folder structure).
- Lessons 11 and 12 carry no teaching slides and deviate from the standard file
  set — see **Assessment Lessons**.

## Beamer Slide Deck Structure (TopicName.tex)

### 1. **Core Concepts** Section

- 4–5 slides introducing fundamental ideas
- Each slide has:
  - Title: concept name
  - `[fragile]` option if it contains `verbatim`
  - Short explanation + code examples
  - Slides should be dense (so they can be shown while I explain on the board or on
    the coding command line)
  - Typefaces are to be sufficiently large so a 2.5m x 3.5m projection can be seen
    from 10 meters

### 2. **Worked Examples** Section

- 2 or more worked examples
- Each: task slide + solution slide
- **Task slide** format:
  - Title: "Worked example N"
  - Fully specified **word problem** (not a list of ideas)
  - OR show Python code and ask to predict output / debug
- **Solution slide** format:
  - Title: "Worked example N (solution)"
  - `[fragile]` if it contains `verbatim`
  - Complete working code or explanation

### 3. **In-class Tests** Section

- Exactly 2 in-class tests (graded exercises)
- Each: task slide + solution slide
- **Task slide** format:
  - Title: "In-class test N"
  - No grading rubric/hints on the task slide
  - Fully specified **word problem** narrative
  - Students solve in ~10 minutes
- **Solution slide** format:
  - Complete working code or solution

### 4. **Further Tasks** Section

- **Further tasks slide**: 6–8 creative word problems (finance-themed scenarios)
  - Primarily take examples from the corresponding python_psz topic page(s) for the
    lesson, recast into finance scenarios
  - NOT generic ideas ("write a script that...")
  - FULLY SPECIFIED scenarios with context and requirements
  - Examples: bond maturity check, portfolio validator, loan threshold, dividend yield
  - Numbered list with paragraph descriptions containing the full specified problem
  - Titles can be descriptive, but each item must still be a complete word problem
- The deck itself has **no quiz slide**. Quizzes are delivered as separate
  notebooks — see **Quiz Notebooks** below.

## Assessment Lessons (11 and 12)

### Lesson 11 — `11_PracticeAndMockExam`

- **No new material.** The whole 90 minutes is revision: the class works through
  problems and then sits a mock exam.
- No Core Concepts, no Worked Examples, no In-class Tests, **no quiz**.
- Deck sections:
  - **Practice** — the python_psz practice sheet, worked through: the `math`,
    `datetime`, `pandas` and `plotly` module exercises plus the three composite
    tasks (the composite stocks task is the natural spine, being finance-shaped)
  - **Mock exam (task)** — a full, exam-length paper covering the whole course,
    modelled on the sample midterms (ZH1 / ZH2)
  - **Mock exam (solutions)** — complete worked solutions
- Support files: `PracticeAndMockExam_class.py` (worked practice-sheet solutions),
  `PracticeAndMockExam_mockexam.py`, `PracticeAndMockExam_mockexam_solutions.py`
  (no `_test1.py`, `_test2.py`, or quiz notebooks)

### Lesson 12 — `12_Exam`

- The real in-class exam. No teaching slides, no tests, no quiz.
- `Exam.tex` — the exam paper itself (printable; not a lecture deck)
- `Exam_solutions.tex` — the full solutions
- `Exam_solutions.py` — runnable reference solutions
- Any data files the exam needs live in the same folder
- Format and difficulty follow the sample midterms (ZH1 / ZH2) and must not exceed
  the material covered in Lessons 1–11

## Python/Text File Companions

For each teaching lesson (**1–10**), create the class deck and its class companion
first. Add tests and quizzes only when requested. Lessons 11 and 12 follow
**Assessment Lessons** above instead.

### `LessonName_class.py` (or `.txt`)

- All core concept examples, all worked examples
- Further task solutions when the slide contains them
- Organized by section headers: `# ============================================================`

### `LessonName_test1.py` (or `.txt`)

- Fully worded problem statement as comments
- Solution code matching the task slide
- Matches the **In-class test 1 (task)** slide exactly

### `LessonName_test2.py` (or `.txt`)

- Fully worded problem statement as comments
- Solution code matching the task slide
- Matches the **In-class test 2 (task)** slide exactly

### No further\*.py files

- Further tasks stay on the slide only; no separate files

## Quiz Notebooks (only when requested)

- For each teaching lesson (**1–10**), create exactly **two quiz notebooks**:
  `LessonName_quiz1.ipynb` and `LessonName_quiz2.ipynb`. Lessons 11 and 12 have
  no quiz notebooks (see **Assessment Lessons**).
- Each notebook contains exactly **2 exercises** (2 + 2 = 4 exercises per lesson,
  split across the two notebooks), testing skills taught in that lesson.
- Each exercise is exactly two cells, in order:
  1. A **markdown cell** with the fully specified, finance-themed word problem.
  2. A **code cell** directly below it containing the answer.
- Every question must explicitly state that its answer cell must run **on its
  own**, with a single "Run Cell" command, independent of any other cell in the
  notebook. Consequently, if the solution needs a module, the `import` statement
  must be inside that same code cell rather than assumed from elsewhere in the
  notebook.

## Key Pedagogical Rules

### Content source (per lesson)

- Draw core concepts, examples, and tasks from the python_psz topic page(s) named for
  that lesson in the Lesson Plan table above.
- Read the local HTML page(s), adapt the explanation into English, and recast the
  examples into concrete finance scenarios.
- For the pandas and visualization lessons, use the sample datasets shipped with the
  mirror (`covid.csv`, `imdb.csv`, `kosar.csv`/`kosar.json`, `olimpia.csv`,
  `szeged.csv`, `games.csv`); prefer finance-relevant framing where possible.

### Word Problems (Non-negotiable)

- All tasks must be **fully specified, real-world scenarios**
- GOOD: "A customer deposits $5,000 at 4% annual interest. Calculate the balance
  after 2 years."
- BAD: "Write a script that calculates compound interest"
- Further tasks must be concrete finance scenarios, not generic instructions

### Types & Printing

- Show conversions explicitly when it is important, but usually stick to pythonic code
- Expose gotchas (e.g., `bool("False")` is `True`)

### Initialization

- Every example shows variable initialization on the first line, so that code runs
  out of the box

### Code Length & Layout

- If Python code exceeds slide height:
  - Continuation slides use `[t,fragile]` (top-aligned, not centered)
  - The continuation slide does not have a title
  - Content starts at the top of the continuation slide
- If still too long, split across multiple slides with continuation

## Build Process

The agent will automatically, for each lesson:

- Create `NN_TopicName/TopicName.tex` with the Beamer structure above
- Create the supporting `.py` files as specified above
- Build the PDF: put intermediate files into a `build/` subdirectory, then copy
  `*.pdf` and `*.synctex.gz` back to the parent directory where the `.tex` file is
- Requires the shared Beamer style file `pqmfcourse-beamer.sty` at the project root
